# MIP 用户信息与使用统计

压汞软件现已包含 BET 的使用统计功能，并使用独立的应用标识、安装标识和客户端配置。生产服务通过应用标识区分 BET 和 MIP；仓库也保留可使用独立数据库部署的服务端代码。

## 软件里的入口

主窗口右下角“隐私设置”按钮和齿轮中的“用户信息统计”标签暂时隐藏，统计设置与功能保留。保留的设置页可显示启用状态、接收地址和本机待发送记录数量，“详情”说明记录内容及保留规则。

新安装默认勾选“启用使用统计”。配置有效的压汞统计服务地址后才会记录和发送；未配置地址时，勾选表示保存的偏好，不会收集或发送统计。用户取消勾选并保存后，重启仍保持关闭。使用统计是否开启不影响文件导入、计算、绘图或导出。

## 记录的内容

- 软件版本、随机安装标识、操作系统与系统语言、屏幕分辨率和缩放。
- SMP 导入的仪器型号类别、成功或失败、耗时和固定错误码。
- 孔径分布、Mayer–Stowe、孔结构以及结果表的页面访问。
- Excel、PDF 导出结果与耗时。
- 每次启用后的打开时长和活跃时长。活跃指窗口在前台且最近两分钟内有操作，仅记录累计秒数，不记录输入内容。

不会记录实验数值、样品名、文件名、路径、异常正文或按键内容。服务器会收到连接 IP；IP 地域显示使用服务器本地数据库，不把 IP 转发给第三方。随机安装量用于估计活跃安装数，不等于真实人数。

客户端队列最多 500 条，只保留最近 7 天，发送失败会在后台重试。服务器沿用 BET 的长期保留策略，并在用户详情页明确说明。关闭统计会清空本机待发送记录和安装标识，停止后续发送；已发送的请求无法撤回。重新开启会生成新安装标识。更换已有接收地址后需要重新开启。

## 配置接收地址

本仓库没有附带管理密码。`telemetry_config.json` 被 Git 忽略；打包时两个 `.spec` 在该文件存在时把它打入 EXE。

复制根目录 `telemetry_config.example.json` 为 `telemetry_config.json`，把 `endpoint` 填为该服务的 HTTPS 事件接口。源码运行时放在项目根目录；打包后放在 EXE 同一目录。例如：

```json
{"endpoint":"https://stats.example.org/mercury/api/v1/events"}
```

上面的域名仅为示例。配置优先级依次为 `MERCURY_TELEMETRY_URL` 环境变量、EXE 旁配置文件、包内配置文件。空地址或无效地址会禁用收集和发送，不会退回其他地址。客户端不会读取 `BET_TELEMETRY_URL`。

## 管理后台

独立后台保留 BET 的使用明细、版本覆盖、活跃安装、按日期/小时的使用量、仪器与导入结果、导出结果、页面使用、打开和活跃时长、IP 和地域筛选等能力。后台需要认证，客户端不包含后台密码。

事件携带 `app_id=mercury_smp`。生产环境使用 BET 的统计服务（2026-11 起支持多软件）：接收地址为 `https://dragonscience.top/bet-telemetry/api/v1/events`，后台 <https://dragonscience.top/bet-stats/> 中 BET 与 MIP 同图显示（MIP 为黄色线），IP 统计有“软件”列和软件筛选。该服务按 `app_id` 校验各自的字段白名单；BET 服务升级前不能接收 MIP 事件。本仓库 `telemetry_server/` 保留为独立部署的备选方案，目前未使用。

服务端依赖、HTTPS、账号、数据库、地域数据和部署方式见 [统计服务部署说明](../telemetry_server/DEPLOY.md)。本次代码移植不自动创建或部署线上服务。
